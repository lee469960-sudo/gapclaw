## ADDED Requirements

### Requirement: 复核缺口必须结构化且有新证据价值

当完成度复核拒绝候选 FINAL 时，复核器 MUST 以结构化缺口卡片给出每一项阻塞理由。每张卡片 MUST 包含原始用户目标中的可验证需求、当前缺少的证据、一个尚未执行的具体工具动作及该动作的预期判定条件。运行时 MUST 验证四个字段完整，并以动作的规范化工具签名、已有执行结果、已物化路径及已读取内容判断其是否仍有新证据价值。字段不完整、仅要求“再检查/再推理”、已被现有证据满足、已执行，或可直接由已缓存结果取回的卡片 MUST 作为非阻塞备注，且 MUST NOT 拒绝 FINAL。

#### Scenario: 完整且未执行的缺口阻止只读 FINAL

- **WHEN** 复核卡片指向一项原始用户需求，声明当前缺失证据、未执行的具体读取/查询动作及预期判定条件
- **THEN** 运行时把该卡片作为有效缺口并向模型回灌该动作

#### Scenario: 重复或散文式缺口不阻止 FINAL

- **WHEN** 复核只提出“再核对一下”，或要求的规范化工具签名已执行、已缓存或其判定条件已由现有证据满足
- **THEN** 运行时将其记录为非阻塞备注并接受候选 FINAL

### Requirement: 每个有效缺口的取证次数有界

对同一有效缺口，运行时 MUST 最多允许两次取证动作，且两次动作的规范化工具签名 MUST 不同。第二次动作完成后仍未满足该缺口时，运行时 MUST 不再为该缺口重复工具调用或推理。对只读/分析任务，运行时 MUST 收尾为明确标注条件、证据和未验证项的最终回复。

#### Scenario: 第二次不同取证后以条件性结论收尾

- **WHEN** 只读/分析任务的有效缺口已完成两次不同规范化签名的取证动作且仍无法满足判定条件
- **THEN** 运行时不再继续该缺口的工具调用或复核循环
- **AND** 最终回复说明已有证据、结论适用条件和仍未验证的项

#### Scenario: 相同签名不能作为第二次取证

- **WHEN** 模型为同一有效缺口重复请求相同规范化工具签名
- **THEN** 运行时不执行该动作，也不把它计为第二次取证

### Requirement: 终结策略按实际动作风险分层

运行时 MUST 根据实际待执行工具动作而非模型文字将任务分为只读/分析或高风险。读取、查询和无副作用的 Shell 命令属于只读/分析；写入、删除、网络外发、部署、支付，以及无法静态判定副作用的 Shell 命令属于高风险。高风险任务的未解决有效缺口 MUST 不被条件性 FINAL 自动放行：运行时 MUST 输出已取得证据和未完成项，并请求用户确认或补充授权。运行时 MUST NOT 因该收敛机制自行执行高风险动作。

#### Scenario: 只读查询允许条件性收尾

- **WHEN** 未解决缺口仅需读取或查询，且其取证次数已用尽
- **THEN** 运行时按条件性结论收尾

#### Scenario: 高风险 Shell 命令需要确认

- **WHEN** 未解决缺口要求写入、删除、外发、部署、支付或无法静态判定副作用的 Shell 命令
- **THEN** 运行时不自动执行该动作，也不宣称任务完成
- **AND** 输出证据、缺口与需要用户确认或授权的动作

## MODIFIED Requirements

### Requirement: 子任务证据门

LLM 自主生成的 PLAN 子任务 MUST 作为进度提示和复核上下文，但 MUST NOT 单独阻止候选 FINAL。运行时在调用完成度复核前 MUST 只依据原始用户目标中可验证但未满足的需求，以及经校验仍具新证据价值的复核缺口决定是否继续。未完成 PLAN 子任务可被回显给模型作为建议，但 MUST NOT 丢弃本轮 FINAL、MUST NOT 作为独立结束门，也 MUST NOT 绕过完成度复核。

#### Scenario: PLAN pending 不阻止有证据的 FINAL

- **WHEN** 模型输出 FINAL，且仅存在 LLM 生成的 `pending` PLAN 子任务，但候选已满足原始用户目标
- **THEN** 引擎仍将候选送入完成度复核

#### Scenario: 未完成子任务不送复核

- **WHEN** 模型输出 `FINAL:`（或完成信号候选）且存在 `status != done` 的具名 PLAN 子任务
- **THEN** 引擎不因该子任务单独阻止完成度复核
- **AND** 该 FINAL 仍按原始用户需求与有效结构化缺口处理
- **AND** 教练提示可以包含未完成子任务文本作为建议

#### Scenario: 无子任务仍复核

- **WHEN** 子任务清单为空（或没有具名条目）且模型输出 FINAL
- **THEN** 引擎仍调用完成度复核

#### Scenario: 证据门丢掉 FINAL 后同轮工具仍执行

- **WHEN** 本轮同时包含 FINAL 与其它工具步骤，且复核产出尚未完成原始用户需求的有效结构化缺口
- **THEN** FINAL 不被接受
- **AND** 其余工具步骤按既有安全门继续执行

#### Scenario: 原始用户需求仍缺失时不接受 FINAL

- **WHEN** 候选 FINAL 缺少原始用户目标中的一项可验证需求
- **THEN** 引擎不接受 FINAL
- **AND** 仅在复核产出有效结构化缺口后继续取证

#### Scenario: 建议性子任务仍向模型可见

- **WHEN** 候选 FINAL 出现且 PLAN 中有未完成具名子任务
- **THEN** 引擎在复核上下文和进度回显中保留该子任务
- **AND** 不因该子任务单独丢弃 FINAL

### Requirement: 完成度复核连续拒绝后收敛

对候选 FINAL 的完成度复核返回有效结构化缺口时，引擎 MUST NOT 无限空转到预算耗尽。运行时 MUST 按缺口跟踪取证动作；每个缺口最多允许两次具有不同规范化签名的取证。一次非缓存的成功取证 MUST 更新该缺口的证据状态。所有剩余缺口均无效、已满足、无新证据价值或已耗尽时，引擎 MUST 收敛而非继续复核循环：只读/分析任务接受带条件候选，高风险任务进入用户确认收尾。

#### Scenario: 耗尽的只读缺口不空转

- **WHEN** 只读/分析任务的唯一有效缺口已用尽两次不同取证动作
- **THEN** 引擎在预算耗尽前收敛为条件性最终回复

#### Scenario: 连续有效拒绝后接受候选

- **WHEN** 完成度复核反复返回同一已耗尽、已满足或不具新证据价值的有效结构化缺口
- **THEN** 引擎收敛当前候选并记录该缺口的处理原因

#### Scenario: 拒绝循环不空转到预算耗尽

- **WHEN** 完成度复核持续返回有效结构化缺口
- **THEN** 引擎在每个缺口的两次取证上限内收敛，不空转至 `max_iters` 耗尽后才丢弃最终答案

#### Scenario: 工具成功清零连续计数

- **WHEN** 某有效缺口已有取证记录，随后一次不同规范化签名的非缓存工具执行成功
- **THEN** 运行时更新该缺口的证据状态
- **AND** 先前的重复签名不会被重新允许

#### Scenario: 高风险缺口耗尽后请求确认

- **WHEN** 高风险任务的有效缺口已用尽其取证动作
- **THEN** 引擎在预算耗尽前输出确认请求
- **AND** 不自动接受为已完成，也不自动执行高风险动作
