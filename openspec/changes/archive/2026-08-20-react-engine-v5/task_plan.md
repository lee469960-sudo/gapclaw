# Task Plan — react-engine-v5

> 执行映射。**不重新定义需求**——需求的唯一正式来源是 `tasks.md`（其又源自 `specs/agent-runtime/spec.md` 与 `design.md`）。本文件只把 `tasks.md` 的 9 组任务映射为可执行阶段，并标注依赖顺序与验收口径。

## 执行阶段映射

| 阶段 | 对应 tasks.md 组 | 主题 | 依赖 |
|---|---|---|---|
| A | 1.x | 非 FINAL 退出前持久化最新状态（高危 #1） | 无 |
| B | 2.x | 原生 tool_calls 全程配对（高危 #2） | 无 |
| C | 3.x | 动态软提示/进度块不被截断丢弃 | 无 |
| D | 4.x + 5.x | 完成度复核连续拒绝收敛 + fix_list 回灌 | A/B/C 之后更稳 |
| E | 6.x + 7.x + 8.x | 卫生项：mcp_results 有界 / 原生裁剪 / 文案与死分支 | 无 |
| F | 9.x | 测试与回归 | 全部实现项之后 |

## 执行顺序与理由

1. **先 A、B**：两条高危缺陷（checkpoint 失效、协议 400）最可能静默失败真实长任务，先修。
2. **再 C**：动态层裁剪保护独立且直接改善长任务可观测性。
3. **D 在 A/B/C 之后**：复核收敛涉及 `_reflect_final` 循环路径，待前几项稳定后再动，减少回归面。
4. **E 随时可做**：纯卫生/清理，不改变外部行为。
5. **F 收尾**：覆盖 1–8 各组的单测，最后跑全量回归。

## 验收口径（对齐 7 条铁律）

- 每个任务勾选前，必须同时满足：`tasks.md` 对应行的 acceptance 已实现 + 有测试覆盖（F 组单测） + 全量回归绿。
- 不新增任何静态硬门禁 / 计数器 / 阈值；D 阶段的「连续 FAIL 计数」是止损兜底、非循环门禁（见 design.md D4）。
- 实现中发现的问题一律记 `findings.md`，完成事实记 `progress.md`，两者都不动 `tasks.md` 的勾选逻辑。
