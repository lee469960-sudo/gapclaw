## Context

现有 local 发布把平台注册表与 Manifest 的相同字段暴露给用户，且依赖字段不会安装工具。见 proposal.md 的动机。本 change 以平台默认发布档案取代 Manifest 覆盖，并把工具准备分为镜像系统工具和仓库锁定应用依赖。

## Goals / Non-Goals

**Goals:**

- 删除 Manifest Local 发布 UI 与其作为新 Run 输入的语义。
- 在不让模型任意安装系统包的前提下，自动准备仓库声明的应用依赖。
- 在对话中以一次确认完成可审计的标准 local 发布。

**Non-Goals:**

- 不把 Git 凭据自动升级为发布凭据。
- 不允许模型从任意 URL 或包名安装系统工具。
- 不自动重试有副作用的发布命令。

## Decisions

### 平台默认档案替代 Manifest 发布字段

标准发布档案由平台按项目解析，包含凭据引用、入口策略、网络和验证计划。历史数据库列可以保留迁移兼容，但控制面、冻结契约和 UI 不再读取它们。

### 两层依赖准备

发布镜像包含固定系统工具。依赖准备器只识别仓库实际存在的锁定文件，并在 run-local 目录安装；Claude Code 只负责发现与解释，平台负责受控执行。

### 命令发现与一次确认

Claude Code 扫描 CI 文件和脚本，生成候选入口。只有唯一安全入口可进入确认；多个候选或未知入口要求用户选择，确认后平台执行一次。

## Risks / Trade-offs

- [仓库缺少锁定文件] → 不猜测依赖，提示用户补齐项目依赖声明。
- [发布脚本需要未预装系统工具] → fail closed，并由镜像构建补充固定工具。
- [多个 CI 入口] → 不自动选择，要求对话确认具体入口。
- [历史 Manifest 字段仍在数据库中] → 保留只读兼容，不作为任何新发布权限来源。

## Migration Plan

1. 先移除 Manifest 表单字段及保存/校验路径。
2. 将新 local 发布 Run 改为读取平台默认档案，忽略历史 Manifest local 字段。
3. 构建并发布含系统工具的可信多架构发布镜像。
4. 验证单次确认发布闭环；回滚时恢复旧应用版本，历史字段不需要数据删除。
