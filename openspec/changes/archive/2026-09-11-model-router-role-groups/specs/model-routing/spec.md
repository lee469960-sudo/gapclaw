## Purpose

为单独配置的聊天模型提供能力声明、角色模型组、受限 LLM 选择、任务级冻结和脱敏审计，使模型选择可配置、可解释且不造成重复执行。

## ADDED Requirements

### Requirement: 单模型必须声明可路由能力

系统 SHALL 允许每个叶子 LLMResource 声明机器可读的能力元数据，至少包括可担任的角色、支持的输入模态、上下文上限、成本档、延迟档和可用运行时。缺少有效能力元数据的叶子模型 SHALL 继续可被直接绑定或被兼容型 LLM Group 使用，但 MUST NOT 作为自动模型路由候选。

#### Scenario: 能力完整的模型可加入路由候选

- **WHEN** 管理者保存具有有效角色和运行时能力的叶子模型
- **THEN** 系统允许该模型被相容的角色模型组引用
- **AND** 仅向 ModelRouter 提供其脱敏能力元数据

#### Scenario: 缺少能力元数据不参与自动路由

- **WHEN** 叶子模型没有可路由能力元数据
- **THEN** 系统不将该模型作为自动路由候选
- **AND** 直接绑定和既有兼容型 LLM Group 行为保持不变

### Requirement: 角色模型组定义首选与有序降级

系统 SHALL 支持 General、React-Code、Planner、Multimodal 和 Fast 角色模型组。每个角色模型组 MUST 配置一个首选叶子模型、零个或多个有序降级叶子模型、预算和超时；成员必须与该角色及其声明的运行时兼容。现有 `type=group` LLM Group SHALL 保持按成员顺序的兼容型故障转移语义，不得被自动转换或重新解释为角色模型组。

#### Scenario: 保存有效角色模型组

- **WHEN** 管理者为 Planner 角色保存首选模型、一个兼容降级模型、预算和超时
- **THEN** 系统保存该角色模型组
- **AND** 路由策略可引用该组

#### Scenario: 不兼容成员被拒绝

- **WHEN** 管理者尝试把未声明 React-Code 角色或不支持 React 运行时的模型加入 React-Code 角色组
- **THEN** 系统拒绝保存并返回可行动原因

#### Scenario: 既有 LLM Group 保持兼容

- **WHEN** 现有 Agent 继续绑定既有 `type=group` 资源
- **THEN** 该 Agent 仍按原成员顺序执行故障转移
- **AND** 不因角色模型组功能而自动改变绑定或成员顺序

### Requirement: ModelRouter 受约束地选择角色和叶子模型

系统 SHALL 使用一个独立、单模型配置的 Router LLM，在合格候选模型组中输出结构化角色与首选叶子模型选择。路由前 MUST 确定性过滤不兼容运行时、输入模态、上下文、预算或不健康的候选；Router LLM MUST NOT 从被选择的候选组中递归选择自身。模型名称本身不得作为任务分类或能力判断的硬编码依据。

#### Scenario: Router 在合格候选内选择

- **WHEN** Standard/React 任务开始且路由策略已启用
- **THEN** 系统先按能力和策略过滤候选
- **AND** Router LLM 仅从过滤后的候选角色组中输出结构化选择

#### Scenario: 图片附件强制多模态候选

- **WHEN** 任务含有实际图片、音频或其他声明的媒体附件
- **THEN** 系统仅允许支持对应输入模态的候选模型参与选择
- **AND** 用户文本中出现媒体词汇本身不触发此门槛

#### Scenario: 路由结果无效时安全失败

- **WHEN** Router LLM 超时、输出无效角色或输出不在合格候选集内的模型
- **THEN** 系统不得扩大候选集或回退到所有已配置模型
- **AND** 按路由策略的明确默认角色处理，或返回可行动的模型不可用原因

### Requirement: 路由决策可脱敏审计

系统 SHALL 为每次模型路由、冻结和降级记录结构化审计事件，至少包括任务分类、候选标识、过滤原因、最终角色和模型标识、降级原因、路由耗时及冻结状态。审计事件 MUST NOT 包含完整用户提示词、模型密钥或未选择模型的工具结果。

#### Scenario: 会话可查看路由决策

- **WHEN** 一次任务完成初始模型选择
- **THEN** 会话执行详情提供默认折叠的模型路由记录
- **AND** 用户展开后可查看脱敏决策字段
