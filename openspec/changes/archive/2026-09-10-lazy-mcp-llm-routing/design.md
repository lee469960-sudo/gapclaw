## Context

当前 `SystemPromptBuilder.build_tools_desc` 会遍历 `mcp_ids` 并为每个 MCP 获取工具目录，因此在主 LLM 开始 ReAct 循环前已经访问了全部已绑定 MCP。MCP 模型已有 `name`、`tags`、`description` 元数据，运行时已有单次运行会话复用和目录缓存能力。详见 [proposal.md](proposal.md) 与本变更的 `agent-runtime` delta spec。

## Goals / Non-Goals

**Goals:**

- 在不使用 MCP 名称到业务场景硬编码映射的前提下，让 LLM 以能力元数据决定初始和补充的 MCP 集合。
- 保证未选 MCP 在该次运行中不被连接、枚举目录或因缓存而访问。
- 保留已选 MCP 的会话复用、正确工具分派和单 MCP 兼容行为。
- 为路由行为提供可测试、脱敏的审计证据。

**Non-Goals:**

- 不改变 MCP 协议、各 MCP 服务的工具定义，或以静态规则替代 LLM 路由。
- 不把完整 MCP 工具目录加入路由提示词，也不让路由模型直接调用 MCP 工具。
- 不在本变更中引入新的外部路由服务或强制迁移已有空描述 MCP。

## Decisions

### 1. 两阶段 LLM 工作流：先选能力，再发现工具

在构建主 Agent 工具目录之前，运行时构造一个小型路由请求。其输入仅包含用户目标、必要的运行阶段/已获证据摘要、用户显式点名（如有）以及候选 MCP 的 ID、名称、标签、描述；它不包含 `tools/list` 结果。默认复用 Agent 已配置的 LLM，避免引入另一套业务理解或外部依赖。

路由响应使用受限 JSON 结构：`selected_mcp_ids`、`reason` 和可选的 `needs_more_capability`。服务端把 ID 限制为本次的合格候选集，去重后得到 `0 / 1 / N` 个选择；解析失败、超时或低置信度均产出空集。名称点名只进入该输入作为强信号，绝不成为绕过 LLM 的静态分流规则。

替代方案是把所有 MCP 目录传给主 LLM 再自行选工具。该方案延续了当前的连接和 token 成本，且无法达成完全惰性加载，故不采用。

### 2. 选择集是目录发现和工具执行的唯一授权边界

目录构建器只接收已验证的选择集，才对其中的 MCP 执行缓存读取或 `tools/list`；没有进入选择集的 MCP 不触发任何网络或 stdio 操作。主 Agent 的 MCP 调用解析同样只从已发现的目录中解析工具，因此不能借由模型伪造 MCP ID 访问未选的 MCP。

现有按工具名定位 MCP 的行为保留，但搜索范围缩小至已选 MCP。单 MCP Agent 保持同一路径，只是先经路由得到该 MCP。

### 3. 用显式能力请求驱动受限补选

主 Agent 需要已选目录之外的能力时，以新的受解析协议指令请求补选，而不是猜测工具名或让运行时全量重试。运行时也可在已选 MCP 不可达或其已加载目录中没有所需工具时请求补选。补选路由携带初始路由的同类元数据，加上已选 MCP、已加载结果和触发摘要；它只允许返回未选候选。

每次运行维护补选计数，最大值为 2。重复选择、无候选、失败或没有新 MCP 的结果不会发起目录发现。达到上限后，主 Agent 获得明确的软提示，基于已有证据完成答复或请求用户澄清。

替代方案是每轮 ReAct 自动重新路由。它会增加延迟并造成新的选择循环，故不采用。

### 4. 元数据门槛与渐进迁移

候选构造要求至少一个非空的 `description` 或 `tags`。不符合条件的 MCP 仍保存为 Agent 绑定项，不删除也不阻断其他 MCP；配置 API/UI 需清晰显示该 MCP 不参与自动路由及补齐路径。这样避免为旧数据进行破坏性迁移，同时确保 LLM 的选择依据是能力文本而非名称猜测。

### 5. 缓存和审计均以选择集为界

目录缓存键包含 MCP 标识及其变更版本（或短 TTL），且只在 MCP 被本次选择后读取或写入。目录缓存命中可省去该已选 MCP 的 `tools/list`，但永不使未选 MCP 变成可见或可访问。

每次初始路由与补选都在运行记录中追加脱敏事件：请求摘要、候选 ID、已选 ID、理由、触发条件、补选序号、目录加载状态及失败类别。事件不保存完整路由提示词、请求参数中的密钥或 MCP 认证信息。沿用运行记录/日志的既有保留与访问控制，避免新建宽权限审计存储。

## Risks / Trade-offs

- [额外一次 LLM 调用增加首轮延迟与费用] → 路由提示只包含紧凑元数据；只在初始和最多两次补选时调用。
- [描述质量不足导致漏选] → 缺失元数据不参与候选，配置界面显式提示；用户点名是强信号但仍接受 LLM 和权限校验。
- [LLM 输出不可靠或被提示注入影响] → 使用受限 JSON、服务端候选集交集、空集失败策略；不接受任意 MCP ID 或工具目录。
- [跨域请求漏掉第二个 MCP] → 允许多选和受限补选，并测试跨域选择。
- [缓存过期导致目录陈旧] → 以 MCP 变更版本或 TTL 失效；失效时仅重新发现已选 MCP。

## Migration Plan

1. 部署候选元数据校验、LLM 路由、选择集门控和审计事件，保持缺少元数据的旧绑定可保存但不可自动选择。
2. 在 MCP/Agent 配置界面提示管理员补齐描述或标签，并观测路由审计事件中的空选择与补选率。
3. 若需回滚，关闭路由功能并恢复既有全量目录构建路径；不会损坏 MCP 绑定或缓存数据。
