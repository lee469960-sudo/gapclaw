## Context

当前运行时把普通对话和需要工具的复杂任务放在同一 ReAct 循环中。已有 MCP、PLAN、完成度复核和软提示机制必须继续服务于复杂任务，但普通对话不应为这些机制支付额外轮次。

## Goals / Non-Goals

**Goals:**

- 在首次 LLM 调用前确定请求模式，并为普通对话提供单轮快速路径。
- 用确定性输出指纹与状态快照识别重复/无进展循环。
- 为不同模式应用独立预算，保留显式工具意图和高风险人工确认。
- 记录足以验证轮次下降和停止原因的脱敏指标。

**Non-Goals:**

- 不更换模型供应商、MCP 协议或工具授权模型。
- 不改变已有工具调用格式、MCP 惰性加载规则或复杂任务的业务语义。
- 不把所有停止事件都升级为人工任务。

## Decisions

### 1. 入口处轻量路由，默认普通对话

使用用户输入、最近上下文和显式工具/操作意图做确定性预判。无工具、文件、代码、部署、外部查询或多步骤目标时选择 `chat`；不调用额外 LLM 分类器。无法确定时默认 `chat`，模型在当前请求中明确需要外部能力时才升级。

### 2. 模式隔离的执行控制器

控制器为每次请求建立模式状态和预算：`chat` 默认主调用 1 次、修复 1 次；`task/tool` 沿用现有上限但增加无进展保护；`human_wait` 不再自动调用模型。预算集中于配置对象，便于测试和运行时调节。

### 3. 双层重复检测

每轮保存规范化输出的精确指纹，并记录工具结果、文件/产物、PLAN 和外部状态摘要。先用精确指纹快速判断，再用现有轻量相似度函数处理仅有格式差异的重复；只有在状态快照也未变化时计为无进展。连续两次命中即停止。

### 4. 普通对话跳过任务复核

`chat` 模式的有效文本直接作为最终答案，不要求 `FINAL`、PLAN 或子任务完成度复核。`task/tool` 继续执行现有复核，避免降低复杂任务的可靠性。

### 5. 人工闭环只承接真实不确定性

重复或无进展本身只触发安全停止。仅当缺少关键信息、涉及高风险/权限、存在歧义或一次修复后仍不可靠时转换为 `human_wait`，并携带稳定原因。

### 6. 指标通过统一终态事件记录

在请求终态写入模式、轮次、重试、停止和人工原因；事件不包含完整 prompt、凭据或原始敏感结果。前端可用已有事件流显示简洁状态，详细数据留在审计日志。

## Risks / Trade-offs

- [普通对话被误判为 chat] → 显式工具词、文件/代码/部署意图强制进入任务模式；增加路由回退指标和回归样例。
- [相似度判断误报] → 必须同时满足无状态变化；先采用精确指纹，语义相似仅作辅助。
- [一次修复仍不足以解决复杂问题] → 复杂请求不会走 chat；chat 修复失败时返回澄清或人工闭环，不继续无限循环。
- [旧调用方依赖 FINAL] → 仅对 chat 放宽 FINAL；task/tool 保留原协议和复核。

## Migration Plan

1. 增加模式策略与预算配置，默认开启 chat 快速路径。
2. 接入入口路由、循环保护和终态指标，不改变现有工具协议。
3. 先运行普通对话、显式工具请求、重复输出和人工闭环回归测试，再逐步观察轮次指标。
4. 若出现误判，可临时关闭 chat 快速路径或将预算恢复为旧值；任务型路径无需回滚。
