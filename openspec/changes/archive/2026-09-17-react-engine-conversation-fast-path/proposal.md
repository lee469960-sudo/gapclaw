## Why

普通对话目前可能被送入完整 ReAct 循环，触发 Planner、完成度复核和重复修复，即使没有工具或外部状态需要改变。这会造成 LLM 轮次过高、中间内容重复，并降低最终回答质量。

## What Changes

- 为每个用户请求增加轻量模式路由：普通对话直接走单轮回答，工具/代码/部署/多步骤目标继续走任务型 ReAct。
- 为普通对话增加最多一次的传输、格式或针对性质量修复重试；不再因缺少 `FINAL` 或重复措辞继续循环。
- 为所有自动循环增加无进展和重复输出检测，连续两轮无状态变化时停止。
- 为 `chat`、`task`、`tool`、`human_wait` 分别设置轮次与重试预算，并集中配置默认值。
- 仅在真实不确定性、歧义、权限或高风险操作时进入人工闭环。
- 增加路由模式、轮次、重试、重复停止、无进展停止和人工闭环原因的结构化指标。
- 保持现有工具型任务和显式工具请求的兼容行为。

## Capabilities

### New Capabilities

- `conversation-execution-policy`: 定义普通对话快速路径、模式路由、轮次预算、重复/无进展停止和人工闭环策略。

### Modified Capabilities

- `agent-runtime`: 修改 ReAct 运行时的模式路由、终止条件、重试预算和可观测性要求。

## Impact

- 影响 React/Agent runtime 的请求入口、循环控制、终止判定和运行指标。
- 影响对话事件流中显示的状态与审计字段，但不改变已有工具协议或 MCP 授权边界。
- 需要新增单元测试、运行时集成测试和普通对话/工具任务回归测试。
