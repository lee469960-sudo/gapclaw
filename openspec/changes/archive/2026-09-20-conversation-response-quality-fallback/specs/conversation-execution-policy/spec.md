## MODIFIED Requirements

### Requirement: 普通对话快速路径

系统 MUST 在每个用户请求开始前识别执行模式。无显式工具、文件、代码、部署、外部查询或多步骤目标，且未命中当前 Agent 已绑定能力元数据的请求 MUST 进入 `chat` 模式；复杂普通对话可在该模式内执行一次有界质量检查和补全，但不得进入 Planner、工具发现或完成度复核。绑定能力匹配只读取 MCP 的名称、标签和描述，不得为模式判定提前连接 MCP 或加载工具目录。

#### Scenario: 普通问答单轮结束

- **WHEN** 用户发送普通解释、闲聊、翻译或知识问答，且未要求外部操作且复杂度低
- **THEN** 系统以 `chat` 模式执行一次 LLM 调用并返回有效文本
- **AND** 不执行质量补全、工具调用、Planner 或完成度复核

#### Scenario: 复杂普通问题保留快速路径

- **WHEN** 用户要求总结、拆解、分析或梳理，但不需要外部状态或工具
- **THEN** 系统仍可使用 `chat` 模式
- **AND** 根据回复质量策略最多执行一次质量补全

#### Scenario: 显式工具意图进入任务模式

- **WHEN** 用户要求读取文件、查询数据、执行命令、编写代码、部署或调用指定工具
- **THEN** 系统直接进入 `task` 或 `tool` 模式
- **AND** 不使用普通对话快速路径

#### Scenario: 绑定能力匹配进入任务模式

- **WHEN** 用户使用“帮我看看当前持仓”这类隐含操作表达，且请求词与当前 Agent 已绑定 MCP 的名称、标签或描述匹配
- **THEN** 系统进入 `task` 或 `tool` 模式
- **AND** 在主 Agent 调用前不连接未选 MCP 或加载任何 MCP 工具目录

#### Scenario: 能力词重合的知识问答保持聊天

- **WHEN** 用户仅询问“什么是持仓”等概念，未表达查看、查询、调用或获取外部状态的意图
- **THEN** 系统仍进入 `chat` 模式

### Requirement: 分模式轮次与重试预算

系统 MUST 为 `chat`、`task`、`tool` 和 `human_wait` 分别执行预算。默认 `chat` 最多一次主调用和一次质量修复重试；修复仅限传输失败、空/截断/协议错误、明确偏题或质量检查判定的复杂回复不足。`human_wait` MUST 暂停自动 LLM 循环。

#### Scenario: 普通对话最多一次修复

- **WHEN** `chat` 模式首次调用失败、返回空/截断/协议错误或复杂回复质量不足
- **THEN** 系统最多再调用一次针对性修复
- **AND** 第二次调用后无论结果如何都结束自动循环

#### Scenario: 缺少 FINAL 不触发重试

- **WHEN** `chat` 模式返回有效文本但没有 `FINAL` 标记且质量合格
- **THEN** 系统直接接受该文本
- **AND** 不因缺少内部协议标记而重试

### Requirement: 执行策略指标可审计

每次请求 MUST 记录 `route_mode`、`llm_turn_count`、`retry_count`、停止原因和人工闭环原因（如有）；chat 请求若执行质量检查，还 MUST 记录回复风格、质量检查结果、补全次数和最终质量状态。指标 MUST 脱敏且可用于比较优化前后的轮次。

#### Scenario: 复杂普通对话产生质量指标

- **WHEN** 一次复杂请求完成一次质量补全
- **THEN** 系统记录模式、调用轮次、重试次数、补全原因和终止状态
- **AND** 记录中不包含凭据或完整敏感提示词

#### Scenario: 普通对话产生运行指标

- **WHEN** 一次请求进入终态
- **THEN** 系统记录模式、调用轮次、重试次数和终止原因
- **AND** 记录中不包含凭据或完整敏感提示词
