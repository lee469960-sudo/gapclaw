## Why

现有会话 Tick 只能在 API 进程内尝试按 Cron 触发 Agent：多副本会重复执行，重启或会话忙碌会丢失触发，失败与结果没有可审计的执行记录。需要把它升级为会话级、可恢复且可验证的定时任务闭环，使用户能配置任务并可靠地看到任务完成或失败。

## What Changes

- 新增会话级定时任务能力，支持一次性、固定间隔和 Cron 调度，以及可搜索的 IANA 时区选择（默认 `Asia/Shanghai`）。
- 用独立 Scheduler Worker 与数据库租约、幂等执行记录取代 API 进程内的唯一调度权，支持重启恢复、多副本和一次补跑。
- 为每次执行建立状态台账、重试、同会话顺序排队、会话消息回写和可选渠道通知。
- 支持会话拥有者显式停止当前定时运行，同时停用周期任务并取消尚未启动的实例；取消信号跨 API/Worker 进程持久化传递。
- 收敛任务 API 与授权校验，迁移既有 Tick；旧接口在兼容期内只读，避免双路径执行。
- 提供会话内配置、下次执行、执行历史、失败详情、立即执行、停用、删除与手动重试体验。

## Capabilities

本次补充：拦截空白定时触发与空白成功输出，通过数据库传递独立 Worker 的实际执行步骤，在原会话实时展示模型与工具执行过程；支持跨进程停止正在运行的定时任务；不增加输出删除功能。

### New Capabilities

- `session-scheduled-tasks`: 会话归属的任务配置、可靠调度、执行台账、权限、运行时回写和管理界面行为。

### Modified Capabilities

- `channels`: 为会话定时任务的可选结果通知定义独立、可重试且不重跑 Agent 的投递行为。

## Impact

- API：任务与执行历史路由、授权、数据库迁移及旧 Tick 路由兼容。
- 运行时：新增独立 Scheduler Worker，调用既有会话 Agent 运行路径并记录可观测结果。
- 前端：会话定时任务配置和历史界面。
- 渠道：可选 IM 投递及独立的通知失败处理。
- 部署：新增 Worker、功能开关、灰度观测和可回滚切换流程。
