# Design — react-engine-v16

## Context

v16 在已 apply 的 v15 之上增量新增 4 条需求，目标**用最少的轮次精准完成任务**。根因与证据见 `docs/exploration/react-engine-v16.md`。

## Goals / Non-Goals

**Goals:**
- 识别「声明完成但无 `FINAL`」并把完成声明补上 `FINAL` 语义再送审（治 94 轮空转）。
- 让 Verifier 逐条核对需求口径，堵住「渠道名称没映射」这类实质漏检，同时不重演 103 轮过度拒绝。
- 注入「已完成清单」压缩 resume 重新定位轮次。
- 对 `execute_ads_sql` 做归一化去重 + 大结果取回指引（治 31% SQL 精确重复）。

**Non-Goals:**
- 不新增任何「放弃/截断」类确定性硬停（铁律不变）。
- 不识别负向「无法完成」信号。
- 不做 LLM 语义判等去重（只做规范化参数去重）。
- 不预拆 checklist 缓存（Verifier 现场拆）。
- 不改 group failover / 环检测 / 退避重试 / MCP 连接熔断（v10/v11 已定）。

## Decisions

| # | 决策 | 内容 |
|---|---|---|
| D1 | 完成信号软转换 | 正向完成声明 → FINAL 候选 → Verifier 把关 |
| D2 | 检测机制 | 正则粗筛 + 连续 2 轮疑似才 LLM 确认（软性） |
| D3 | 完成信号范围 | 只正向；负向「无法完成」不纳入 |
| D4 | Verifier 核对 | 现场按 goal 拆 checklist 逐条判 PASS/FAIL |
| D5 | 数据准确性口径 | 字段/数字/映射必须精确，仅排版措辞豁免（去掉「小瑕疵一律 PASS」） |
| D6 | FAIL 衔接 | 定向补，保留完成态，不推翻 |
| D7 | 已完成清单 | 引擎零 LLM 拼，每轮回显，永不裁 |
| D8 | MCP 去重 | 所有 MCP 工具「工具名+归一化参数」进 query_cache；`execute_ads_sql` SQL 归一化为特例；大结果落盘回显取回路径 |

## Rejected Alternatives（不进入 v16）

| 废弃项 | 废弃原因 |
|---|---|
| 完成信号纯正则即时转换（Q4=A） | 缺少 LLM 确认，误转风险高；连续 2 轮 + LLM 确认更软 |
| 负向「无法完成」也软转换（Q10=B） | 「某工具无法连接」≠「任务无法完成」，正则难区分，误转污染 Verifier |
| LLM 语义判等去重（Q7=B） | 每轮都贵且易误判；视图名/SQL 归一化即可覆盖大部分重复 |
| 预拆 checklist 缓存（Q9=B） | goal 常是结构化列清单，现场拆零成本，预拆每任务多一次启动调用 |
| 完整 replan 覆盖（Q5=B） | RUN1 的「拒绝→全量重规划→掉线」正是空转诱因，定向补更稳 |

## Risks / Trade-offs

- [风险] 完成信号软转换误判「任务完成了吗」/「无法完成」→ 用负向词 + 问号过滤 + 连续 2 轮 + LLM 确认三重把关；误转代价 = 一次被拒的 FINAL（Verifier 吸收）。
- [风险] Verifier 逐条核对更严，可能增加拒绝次数 → 定向补 + `_REFLECT_FAIL_CONVERGE` 兜底，不空转。
- [风险] 已完成清单占上下文 → 只回显后 N 条进度 + 文件路径，清单本身豁免裁剪，体量可控。
- [风险] SQL 归一化去重误杀合法分页 → `LIMIT/OFFSET` 不同视为不同查询。
