## MODIFIED Requirements

### Requirement: 普通对话快速路径

系统 MUST 在每个用户请求开始前识别执行模式。无显式工具、文件、代码、部署、外部查询或多步骤目标，且未命中当前 Agent 已绑定能力元数据的请求 MUST 进入 `chat` 模式，并在一次有效 LLM 回复后结束；不得进入 Planner、工具发现或完成度复核。绑定能力匹配只读取 MCP 的名称、标签和描述，不得为模式判定提前连接 MCP 或加载工具目录。

#### Scenario: 普通问答单轮结束

- **WHEN** 用户发送普通解释、闲聊、翻译或知识问答，且未要求外部操作或绑定能力
- **THEN** 系统以 `chat` 模式执行一次 LLM 调用并返回有效文本
- **AND** 不执行工具调用、Planner 或完成度复核

#### Scenario: 显式工具意图进入任务模式

- **WHEN** 用户要求读取文件、查询数据、执行命令、编写代码、部署或调用指定工具
- **THEN** 系统直接进入 `task` 或 `tool` 模式
- **AND** 不使用普通对话快速路径

#### Scenario: 绑定能力匹配进入任务模式

- **WHEN** 用户使用“帮我看看当前持仓”这类隐含操作表达，且请求词与当前 Agent 已绑定 MCP 的名称、标签或描述匹配
- **THEN** 系统进入 `task` 或 `tool` 模式
- **AND** 在主 Agent 调用前不连接未选 MCP 或加载任何 MCP 工具目录

#### Scenario: 能力词重合的知识问答保持聊天

- **WHEN** 用户仅询问“什么是持仓”等概念，未表达查看、查询、调用或获取外部状态的意图
- **THEN** 系统仍进入 `chat` 模式

## ADDED Requirements

### Requirement: 显式资源名称优先进入任务模式

系统 MUST 将用户消息中显式提到的资源型 MCP/工具名称作为操作意图信号。名称匹配 MUST 基于当前运行时提供的绑定资源元数据或通用资源名称识别，不得为单个 MCP 编写硬编码名称。

#### Scenario: 用户点名已绑定 MCP

- **WHEN** 用户消息提到当前 Agent 已绑定的 `okx-trader` 或其他资源名称
- **THEN** 系统进入 `task` 或 `tool` 模式
- **AND** 继续执行绑定校验与后续 MCP 语义路由

#### Scenario: 用户点名未绑定资源

- **WHEN** 用户明确要求使用当前 Agent 未绑定的 MCP/工具名称
- **THEN** 系统进入任务路径
- **AND** 返回可解释的未绑定提示，不生成普通聊天式的模拟查询结果
