## Context

当前 `chat` 快速路径在执行入口使用固定操作词判定，绑定 MCP 的名称、标签和描述只在进入任务循环后用于 MCP 选择。因此隐含外部查询容易被误判为普通聊天，而显式点名未绑定资源又缺少一致的解释性反馈。

## Goals / Non-Goals

**Goals:**

- 在第一次主 LLM 调用前，用已绑定 MCP 的元数据补充模式判定。
- 识别显式资源名称，不硬编码 `okx-trader` 或其他单个 MCP。
- 将未绑定资源请求路由到任务路径并返回可审计的未绑定原因。
- 保持工具目录、MCP 连接和凭据的完全惰性加载。

**Non-Goals:**

- 不改变 MCP 的 LLM 语义选择、授权校验或工具分派协议。
- 不把所有绑定 MCP 的消息强制路由到任务模式。
- 不使用额外 LLM 分类调用，也不引入新的向量数据库或外部依赖。

## Decisions

### 1. 元数据快照参与入口路由

Runtime 只读取当前 Agent 已绑定 MCP 的 `name/tags/description`。显式资源名或“查看/查询/获取”等操作意图与能力 token 命中时进入任务模式；纯概念问答需要操作意图才保持能力匹配，避免“什么是持仓”误触发。

### 2. 通用资源识别而非 MCP 名称硬编码

资源名称识别使用显式操作短语和通用资源名形态（例如带连字符的 provider/tool 名称），绑定关系仍由服务端元数据和授权集合确认。这样新增 MCP 不需要修改路由代码。

### 3. 未绑定请求在任务路径终止

入口在任务循环前比较显式资源名与绑定集合；不匹配时返回稳定错误和 `mcp_not_bound` 终止原因。这样不会让聊天模型生成看似真实的持仓、余额或订单结果。

### 4. 保持后续 MCP 惰性路由不变

进入任务模式后继续使用现有 MCP 候选构建和 LLM 语义路由；入口元数据判定不调用 `tools/list`，不扩大访问范围。

## Risks / Trade-offs

- [隐含意图仍可能无法从短句推断] → 使用绑定能力 token 与通用查看/查询意图组合，并保留显式 `execution_mode=task` 作为回退。
- [资源名形态识别可能误报普通项目名] → 仅对资源后缀/显式操作短语启用，且未绑定时只返回解释性提示，不执行外部动作。
- [数据库元数据读取失败] → 降级到现有固定操作词路由，不建立 MCP 连接。

## Migration Plan

1. 发布入口路由和元数据快照变更。
2. 观察 `route_mode`、`mcp_not_bound` 和 MCP 加载审计事件。
3. 如出现误判，可临时通过 `message_meta.execution_mode=chat/task` 覆盖单次请求；无需回滚 MCP 协议。
