# conversation-response-quality Specification

## Purpose

为普通对话提供面向复杂问题的结构化回复和一次有界质量补全，避免复杂请求被快速路径以单段、过短或未完成的文本直接结束，同时保持简单闲聊的低延迟体验。

## Requirements

### Requirement: 复杂对话应获得适配的回复结构

系统 SHALL 识别总结、拆解、分析、梳理、对比、提取、归纳以及带来源、日期、主题或多条件的复杂表达。复杂表达的普通对话回复 MUST 至少覆盖结论或摘要、关键要点和必要说明中的适用部分；简单问候和短事实问题不得被强制套用长模板。

#### Scenario: 得到大脑主题拆解

- **WHEN** 得到大脑 Agent 收到“梳理、拆解或分析某个主题/日期笔记”的请求
- **THEN** 回复包含明确结论或摘要、分组要点和必要的说明
- **AND** 不因回复处于 chat 模式而退化为无上下文的一句话

#### Scenario: 简单闲聊保持简洁

- **WHEN** 用户发送问候、身份询问或简单事实问题
- **THEN** 系统返回自然、简洁的回复
- **AND** 不额外触发质量补全或 React Engine

### Requirement: 质量补全必须有界且可观测

系统 SHALL 在普通对话首次回复明显过短、未覆盖关键请求词、只复述用户问题或未完成明确的拆解/分析要求时，最多执行一次针对性补全。补全后的结果无论是否满足质量判定都 MUST 结束本轮，且记录质量检查、补全原因和最终状态。

#### Scenario: 首次回复过短

- **WHEN** 复杂请求首次得到明显过短或缺少关键要点的有效文本
- **THEN** 系统最多再调用一次 LLM 请求补全结构化内容
- **AND** 不进入无限重试或完整工具循环

#### Scenario: 二次补全仍不完整

- **WHEN** 一次补全后仍未满足质量条件
- **THEN** 系统返回最后一次结果
- **AND** 运行指标标记质量补全失败或条件性完成

### Requirement: 质量策略不得改变安全和工具边界

质量补全 MUST NOT 自动授予 MCP、Skill、Shell、文件或部署权限；高风险操作、人工确认、未绑定资源和已有 React Engine 工具策略 MUST 保持原有语义。

#### Scenario: 复杂问题不等于工具授权

- **WHEN** 复杂普通问题触发质量补全
- **THEN** 补全只允许使用普通对话上下文
- **AND** 不连接未选择的 MCP 或执行未授权工具
