# 自动模型路由配置说明

自动模型路由会在 Standard Agent 的任务开始前，从已授权且满足能力要求的模型中选择一个执行模型，并在整个任务内固定使用它。它不会替代已有的直接 LLM 绑定：未配置路由策略的 Agent 继续使用原有 `llm_id`。

## 配置顺序

按“单模型能力 → 角色模型组 → 路由策略 → Agent 绑定”的顺序配置。

### 1. 配置单模型能力

在“LLM 管理”中，为每个 `type=llm` 的叶子模型开启“自动路由能力”，并声明：

- 可承担角色：General、React-Code、Planner、Multimodal、Fast；
- 输入模态：例如 `text`、`image`；
- 可用运行时：自动路由目前使用 `react`；
- 上下文上限、成本档、延迟档等能力信息。

没有完整能力声明的模型仍可被 Agent 直接绑定，也可用于旧的 LLM Group，但不会成为自动路由候选。

### 2. 创建角色模型组

进入“模型路由”页面，为每一种角色创建一个模型组，并配置：

- 角色，例如 `planner`；
- 首选模型；
- 按顺序配置的回退模型，可为空；
- 预算与超时。

只有角色、运行时和输入模态都匹配的模型可以加入。比如 Multimodal 组的模型必须声明对应的媒体输入能力。

### 3. 创建路由策略

在“模型路由”页面创建路由策略：

- **Router LLM**：专门理解任务并选择角色/模型的直接叶子模型；
- **角色模型组**：该策略允许参与选择的角色组；
- **默认角色**：当 Router 超时、返回非法 JSON 或选择了候选集外的模型时，系统仅安全回退到该角色的合格首选模型。

Router LLM 不会作为任务执行模型候选，避免递归路由。

### 4. 绑定到 Agent

在“Agent 管理”编辑 Standard Agent 时，保留原有直接 LLM 绑定，并额外选择一个“模型路由策略”。

绑定策略后，任务开始前会自动选择并冻结一个执行模型；不选择策略时，Agent 完全维持原有直接 `llm_id` 执行方式。

## 运行与降级规则

- 每个任务只路由一次。主循环、完成度复核、会话摘要和 MCP 语义选择均复用同一个冻结模型。
- 只有首次模型请求尚未产出有效内容、尚未产生或执行工具调用时发生超时、网络故障或限流，才会按当前角色模型组的回退顺序切换一次。
- 一旦已经有有效输出或执行过工具，系统不会自动换模型重跑，避免重复推理和重复执行。
- 会话“执行过程”中的“模型路由”项默认折叠；展开后可查看脱敏的候选、过滤原因、最终模型、降级原因与耗时。

## 回滚

回滚不需要删除策略或审计记录。在 Agent 设置中清空“模型路由策略”并保存即可：

1. 操作只解除 `routing_policy_id`；
2. 不会修改原有 `llm_id` 或 legacy LLM Group 成员；
3. 下一次任务立即恢复该 Agent 的直接模型执行；
4. 建议发起一个小任务，确认不再产生“模型路由”步骤且使用原直接 LLM。

## 边界

- 既有 `type=group` LLM Group 保持原有按成员顺序的故障转移语义，不应转换为角色模型组。
- Embedding 不进入聊天模型路由，继续通过 `EMBEDDING_*` 配置独立管理。
- Claude Code / Code Profile 不支持绑定路由策略，仍保持单个兼容 LLM 的固定绑定与可复现语义。
